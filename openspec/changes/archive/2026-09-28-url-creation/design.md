## Context

See proposal.md for motivation and specs/url-creation/spec.md for behavior. Inspection found only OpenSpec configuration, skills, and empty main-spec/archive directories: no package manifest, application, tests, or deployment configuration exists. This design therefore establishes the first application structure. The project requires CommonJS and built-in Node.js APIs without third-party dependencies.

## Goals / Non-Goals

**Goals:** Keep HTTP handling explicit, separate startup from request handling so tests can use ephemeral ports, and cover the whole create-to-redirect journey without external services.

**Non-Goals:** Database selection, multi-process operation, public hosting, a client-side application framework, and persistent storage are deferred. The initial process-lifetime storage assumption is documented in the proposal and specification.

## Decisions

1. **Server-rendered HTML with ordinary form submission.** Introduce `src/app.js` for a server factory/request handler, `src/server.js` for startup, and `src/views.js` for HTML rendering. `GET /` renders the form; `POST /shorten` reads a URL-encoded `destination` field and returns HTML containing the form and result (200) or a validation error (400). This needs no client JavaScript. A JSON API plus browser scripting would add a second interface without serving the issue's acceptance criteria.

2. **Explicit destination validation.** Trim input, require an explicit HTTP or HTTPS scheme and hostname using the built-in URL parser, and store its serialized URL. Preserve path, query, and fragment semantics. Do not fetch destinations during validation. Escape all dynamic text and attribute values in HTML. Accept only URL-encoded creation requests (415 otherwise) and cap request bodies at 16 KiB (413 otherwise) to bound buffered input. Regex-only validation and destination reachability checks are less reliable and unnecessary.

3. **Process-local mapping store.** Introduce `src/url-store.js` with a Map from random code to destination. Use seven base64url characters generated by `node:crypto`, retrying on collision before insertion so no existing entry is overwritten; inject the code generator for deterministic collision tests. Repeated submissions may receive separate codes. A file store would introduce recovery and concurrent-write behavior beyond the issue; retaining a small store boundary allows persistence to be added later.

4. **Simple redirect route and trusted displayed origin.** `GET /<code>` returns 302 with the stored destination in `Location`; unknown routes or codes return 404. Match creation routes before codes; use an explicit seven-character base64url code pattern. Build displayed absolute short URLs from configured `BASE_URL`, defaulting to `http://localhost:<PORT>` with port 3000, rather than trusting the incoming Host header. Validate configuration at startup. Proxy inference and permanent redirects are unnecessary for this initial local app.

5. **Built-in test runner and HTTP integration tests.** Add `package.json` with `start: node src/server.js` and `test: node --test`. Unit tests cover validation, escaping, and collision handling. HTTP tests start an isolated server/store on an ephemeral port, submit form data, inspect the resulting link, and follow it with redirects disabled to assert the destination. Tests make no requests to external destinations. A browser smoke check verifies visible labels and that the rendered result can be clicked. No dependency-based test framework is required.

## Risks / Trade-offs

- [Restart loses mappings] → Document the process-lifetime limitation in the README; persistence requires a separate change.
- [Concurrent application processes have different mappings] → Document single-process operation for this version.
- [User input could alter rendered HTML] → Escape dynamic values, restrict destination schemes, and test malicious form input.
- [Configured origin does not match the browser-accessible origin] → Document `BASE_URL` and validate it at startup; integration tests provide the test server's actual origin.
- [Random code collision] → Retry before insertion and test that existing mappings remain unchanged.

## Migration Plan

No existing application data or routes need migration. Add the application and tests, run `npm test`, then smoke-test `npm start` with creation and redirect in a browser. Deployment is outside this change. Rollback consists of reverting the implementation commit; process-local mappings are discarded when the server stops.
